Implement the milestone:

Redesign forms and input workflows.

Primary objective

Transform long forms into guided desktop workflows that:

- minimize scrolling
- reduce cognitive load
- preserve rapid data entry
- surface validation and warnings at the correct time
- keep users oriented
- feel comparable in quality to professional desktop applications

Business Defaults workflow

Convert Business Defaults into a guided workflow consisting of:

1. Business and sales
2. Food and payment costs
3. Labor and event costs
4. Profit target
5. Review and save

The user should be able to:

- move forward
- move backward
- revisit completed sections
- preserve entered values
- save only after successful review

Do not persist partial Defaults while navigating.

Only Save changes should update the database.

Event Inputs workflow

Convert Event Inputs into the agreed guided workflow:

1. Event details
2. Demand and weather
3. Revenue and food costs
4. Labor
5. Event costs and fees
6. Profit target and review

The workflow should support:

- Back
- Continue
- stage indicators
- review before analysis

Only Analyze event should:

- perform final validation
- create the Event
- create the Original estimate Scenario
- open the Event Analysis workspace

Changing stages must never create records.

Stepper behavior

Create a reusable guided-workflow component.

Requirements:

- numbered stages
- current stage clearly highlighted
- completed stages indicated
- invalid stages indicated
- keyboard accessible
- responsive
- reusable for future products

Desktop layouts may use a side stepper.

Narrow layouts may move the stepper horizontally above content.

Both presentations must represent the same logical workflow.

Viewport optimization

Design every normal stage to fit within approximately one desktop viewport
whenever practical.

Use:

- paired fields
- compact repeatable rows
- grouped related inputs
- concise helper text
- progressive disclosure

Avoid:

- excessive scrolling
- huge empty areas
- large decorative spacing
- unnecessary page breaks

Do not force artificial heights or internal scrolling merely to reach the
viewport goal.

Rapid data entry

The guided workflow must remain efficient.

Support:

- logical Tab order
- keyboard-first entry
- Enter where appropriate
- adding multiple labor rows quickly
- adding multiple additional-cost rows quickly
- returning to previous stages without data loss

The workflow should reduce thinking, not increase it.

Validation

Validation answers:

"Can this value be accepted?"

Validation may prevent moving forward when required information is missing or
invalid.

Validation should remain:

- inline
- immediate where appropriate
- consistent with the design system
- attached to the relevant control

Warnings

Warnings answer:

"This event is beginning to look financially risky."

Warnings must:

- remain non-blocking
- appear as soon as sufficient valid information exists
- remain attached to the causal section
- update live
- disappear when no longer applicable

Continue using the established warning logic.

Do not introduce result previews.

Review stage

Create concise review stages rather than another giant form.

Each section should summarize only key information.

Provide Edit actions for each section.

Do not duplicate the complete form.

Review should make it easy to verify assumptions before analysis.

Help content

Keep inline help concise.

Long explanations should use:

- expandable help
- tooltip
- information popover

Do not clutter the normal workflow.

Preserve current contextual explanations including:

- weather percentages
- event protection percentages
- warning explanations

Error recovery

If final submission fails:

- preserve every entered value
- preserve repeatable row order
- preserve stage completion
- open the first invalid stage
- identify all stages containing errors
- focus the first invalid control
- keep inline validation beside the relevant control

Do not discard work.
