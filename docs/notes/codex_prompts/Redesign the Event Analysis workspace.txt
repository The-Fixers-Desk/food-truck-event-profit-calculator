Redesign the Event Analysis workspace into the application's primary

Apply the established V1 design system, shared application shell, and reusable

Do not change business logic, calculations, persistence, routes, database

The live recalculation engine already works correctly.

This milestone is about presenting information so users can make business
decisions quickly and confidently.

Primary objective

The Event Analysis workspace is the centerpiece of the application.

It should receive the greatest design attention of any screen in the product.

If tradeoffs must be made, prioritize:

- decision-making speed
- clarity
- information hierarchy
- workflow efficiency

over implementation simplicity.

The workspace should feel comparable in quality—not appearance—to professional
desktop applications such as:

- Notion
- ChatGPT
- Linear
- Stripe Dashboard
- Bloomberg Terminal (information hierarchy only)

Do not imitate these products.

Use them only as references for:

- information density
- visual hierarchy
- workspace organization
- efficient desktop layouts
- restrained design

Primary design principle

The Event Analysis workspace is not a report.

It is not a calculator.

It is a decision-making tool.

Every design decision should help answer:

"Should I work this event?"

or

"What should I change to make this event worthwhile?"

Workspace structure

Create a persistent two-region workspace.

Left region

Assumptions.

Right region

Business results.

The user should never lose sight of:

- assumptions
- financial outcome

while working.

Do not stack the entire interface vertically unless narrow layouts require it.

Desktop layout

Preferred structure:

LEFT

- scenario controls
- assumption groups

RIGHT

Top

- decision summary

Middle

- primary metrics

Bottom

- detailed financial breakdown

Visual hierarchy

The eye should naturally prioritize information in approximately this order:

1. Business Profit
2. Profit Target status
3. Break-even customers
4. Major warnings
5. Revenue
6. Total costs
7. Supporting calculations

Not every number deserves equal visual weight.

Decision summary

Create a reusable decision summary area.

It should communicate the current business outcome immediately.

Include prominent presentation of:

- Business Profit
- Profit Margin
- Target met or not met
- Break-even customers
- Overall recommendation state

Do not require users to inspect detailed calculations before understanding the
result.

Primary metrics

Create a reusable metrics area emphasizing:

- revenue
- food costs
- labor costs
- fixed costs
- organizer fees
- total costs
- owner pay

Metrics should be:

- scannable
- aligned
- comparable
- visually balanced

Use typography and spacing rather than excessive decoration.

Warnings

Warnings should become actionable.

Instead of merely stating:

High competition

Prefer messages that explain:

- why
- consequence
- approximate impact

Example:

Expected buyers per vendor

68

Break-even customers

102

Approximately 34 additional customers are needed.

When reasonable, include factual guidance derived from existing calculations.

Do not invent optimization recommendations unsupported by current business
logic.

Assumptions panel

Treat assumptions as controls rather than another long form.

Group assumptions into collapsible sections such as:

- Demand
- Revenue
- Labor
- Costs
- Fees

Only one section should normally expand by default.

Preserve all existing live recalculation behavior.

Scenario management

Create a dedicated persistent scenario-management region.

Include:

- Scenario name
- Save
- Save as new
- Reset changes
- Rename
- Compare

These actions should always be easy to locate.

Do not scatter Scenario actions throughout the page.

Live recalculation

Every assumption change should feel immediate.

Users should never wonder whether calculations updated.

Subtle visual acknowledgement is acceptable.

Avoid loading indicators unless a real asynchronous delay exists.

Progressive disclosure

Do not overwhelm users with detailed calculations.

Present:

Top

The answer.

Bottom

The explanation.

Use expandable sections for:

- revenue details
- cost breakdowns
- fee calculations
- assumption explanations

Do not hide critical decision metrics.

Detailed calculations remain available but should not dominate the workspace.

Financial breakdown

Create reusable expandable sections for:

Revenue

Food

Labor

Fees

Additional costs

Profit calculations

Maintain current calculation accuracy.

Do not change formulas.

Comparison readiness

Design the workspace so future comparison interactions naturally align with the
same visual hierarchy.

Do not redesign the comparison screen yet.

Sticky actions

Where appropriate, use the established sticky action patterns for:

Scenario actions

Assumption editing

Important controls should remain convenient without covering content.

Content density

The workspace should feel information-rich without feeling crowded.

Avoid:

- oversized cards
- excessive whitespace
- unnecessary repeated headings
- decorative graphics
- redundant labels

Use:

- typography
- spacing
- alignment
- grouping
- subtle dividers

to create structure.

Desktop optimization

Optimize primarily for widescreen desktop use.

Use available horizontal space efficiently.

Avoid:

- large unused margins
- narrow centered layouts
- unnecessary scrolling
