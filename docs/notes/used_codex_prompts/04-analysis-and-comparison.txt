SUPPLIED ARTIFACTS

Use the packages for:
- 06 Event Analysis Workspace
- 08 Scenario Comparison

PRIMARY OBJECTIVE

Implement the complete decision-making experience: inspect one scenario transparently, adjust it with live recalculation, save versions, and compare multiple scenarios for the same event.

REQUIRED SCOPE

1. Event Analysis Workspace:
   - real event and active-scenario identity;
   - scenario selector/list and status states;
   - key metrics: estimated revenue, total costs, estimated profit, profit margin, and break-even buyers;
   - profitability recommendation tied to the selected user profit rule;
   - transparent cost breakdown;
   - decision checks;
   - factual warnings;
   - assumption/input summary;
   - sensitivity or “what changes the result” cues;
   - event snapshot;
   - edit controls and approved responsive composition.

2. Live interaction:
   - all editable scenario assumptions supported by the existing product;
   - automatic recalculation of every dependent result and warning;
   - exact existing formulas and rounding rules;
   - no stale metric, recommendation, or warning after changes;
   - invalid adjustments cannot corrupt the saved scenario.

3. Scenario actions:
   - automatic original scenario remains intact;
   - save adjustments as a new scenario by default;
   - deliberate overwrite of the active scenario only through the approved explicit path;
   - duplicate scenario;
   - rename/delete where existing product behavior requires it;
   - active scenario and unsaved-change safeguards;
   - persistence after restart.

4. Scenario Comparison:
   - select eligible scenarios belonging to the same event;
   - approved side-by-side key metrics;
   - aligned assumption differences;
   - clear best-option and recommendation signaling without hiding tradeoffs;
   - impact indicators;
   - open a compared scenario back in the workspace;
   - keep/select scenario action;
   - meaningful empty and insufficient-scenario states;
   - desktop columns, compressed tablet view, and usable mobile scenario switching rather than unreadably narrow columns.

5. Semantic states:
   - worth accepting;
   - borderline;
   - not worth accepting;
   - best margin or strongest option where supported;
   - warnings remain factual and derived from the real calculation results.

6. Add or update tests for:
   - live recalculation;
   - all metric and warning dependencies;
   - save-as-new and overwrite paths;
   - duplicate, rename, and delete behavior;
   - persistence after restart;
   - dirty-navigation protection;
   - comparison eligibility and selection;
   - correct assumption differences;
   - opening either scenario from comparison;
   - mobile/condensed comparison behavior where testable.

COMPLETION GATE

Both acceptance checklists must pass, and the existing calculation-engine tests must remain green. Do not substitute static chart values, mock scenario data, or approximate formulas for the real domain engine.
