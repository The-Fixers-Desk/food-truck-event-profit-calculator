Primary objective

composition—not visual imitation—to products such as:

- ChatGPT
- Notion
- Linear
- Stripe Dashboard
- Zillow

Core design principle

Every screen must answer:

“What is the primary job of this screen?”

Then visually subordinate everything that does not directly support that job.

Do not treat all useful information or actions as equally important.

The application should be understandable quickly without presenting every
available action at once.

Visual boundaries

The current application still relies too heavily on visible borders and
outlined containers.

Perform a boundary-reduction pass.

Remove cards, borders, or outlines where grouping can be communicated through:

- spacing
- alignment
- typography
- dividers
- surface contrast
- row structure

Use cards only when they represent:

- an independent task
- a selectable object
- a decision summary
- an elevated status
- a bounded management object

Do not:

- wrap ordinary text links in bordered rectangles
- put every section in a card
- use cards to duplicate navigation
- nest cards without strong semantic reason
- use shadows to compensate for weak hierarchy

Buttons and links

Audit whether repeated buttons should instead be:

- whole-row links
- compact text actions
- overflow-menu actions
- icon-and-label actions
- one shared primary action

Do not preserve a full rectangular button merely because one existed before.

A normal screen should generally have only one visually dominant primary
action.

Secondary actions should be restrained.

Tertiary actions should often be links or overflow actions.

Destructive actions should remain discoverable but quiet until intentionally
opened.
