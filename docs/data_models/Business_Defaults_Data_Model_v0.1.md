# Food Truck Event Profit Calculator

## Business Defaults Data Model v0.1

### Status

Approved for V1 implementation.

### Purpose

This document defines the reusable business assumptions stored by the Food
Truck Event Profit Calculator.

A business default represents information that is expected to apply across
multiple event analyses. Every default may be overridden for an individual
event without changing the stored business default.

Changes to stored defaults apply only to newly created event analyses and to
existing analyses that have not established an event-specific override.

---

## BusinessDefaults

### business_name

- Display name: Business name
- Data type: Text
- Required: No
- Default value: Empty
- Calculation role: None
- Event override: Not applicable
- Meaning: The name used to identify the customer's food truck within the
  application.

### average_order_sale_amount

- Display name: Average order sale amount
- Data type: Currency
- Required: Yes
- Minimum value: Greater than $0.00
- Calculation role: Revenue estimation
- Event override: Yes
- Meaning: The expected average amount of revenue generated by one customer
  transaction.

### food_cost_method

- Display prompt: How do you usually estimate food and packaging costs?
- Required: Yes
- Default choice for fresh setup: Average cost per order
- Choices: Average cost per order, Percentage of sales, or Typical total per
  event
- Calculation role: Variable-cost estimation
- Event override: Yes

Only the confirmed method and its matching value are stored:

- **Average cost per order:** Currency, minimum $0.00.
- **Percentage of sales:** Percentage from 0% through 100%.
- **Typical total per event:** Currency, minimum $0.00.

The unselected values remain empty. Existing percentage defaults are retained
as the Percentage of sales method.

### card_sales_percentage

- Display name: Sales paid by card
- Data type: Percentage
- Required: Yes
- Minimum value: 0%
- Maximum value: 100%
- Calculation role: Payment-processing cost estimation
- Event override: Yes
- Meaning: The expected percentage of event revenue paid through methods that
  incur the saved card-processing fee.

### card_processing_percentage

- Display name: Card processing fee
- Data type: Percentage
- Required: Yes
- Minimum value: 0%
- Maximum value: 100%
- Calculation role: Payment-processing cost estimation
- Event override: Yes
- Meaning: The percentage fee charged on revenue paid by card.

### labor_entries

- Display name: Default labor
- Data type: One or more labor entries
- Required: Yes
- Calculation role: Labor-cost estimation
- Event override: Yes
- Meaning: The typical labor paid at each hourly rate for an event.

Each labor entry contains:

- **Hourly labor rate:** Currency, minimum $0.00.
- **Total hours paid at that rate:** Decimal hours, minimum 0. This represents
  combined worker-hours. Two employees working six hours each equals 12 total
  hours paid.

Default labor cost will be the sum of hourly labor rate multiplied by total
hours paid at that rate across all entries.

### default_owner_labor_pay

- Display name: Default owner labor pay
- Data type: Currency
- Required: No
- Minimum value: $0.00
- Calculation role: Labor-cost estimation
- Event override: Yes
- Meaning: An optional flat amount the owner normally pays themselves for
  working a typical event. It is labor cost and is separate from business
  profit. A blank value means no default owner labor pay has been set.

### default_travel_cost

- Display name: Default travel cost
- Data type: Currency
- Required: No
- Minimum value: $0.00
- Calculation role: Travel-cost estimation
- Event override: Yes
- Meaning: The typical flat travel cost for an event. It is not based on
  mileage.

### profit_target

- Prompt: How do you decide whether an event is worth accepting?
- Required: Yes
- Choices: Minimum profit amount or Minimum profit margin
- Calculation role: Result interpretation
- Event override: Yes
- Meaning: The single target the customer uses to judge whether an event is
  worthwhile. This choice will later control profitability analysis and
  warnings.

When **Minimum profit amount** is selected, a required currency value of $0.00
or more is stored. When **Minimum profit margin** is selected, a required
percentage from 0% through 100% is stored. Only the selected value is retained.

---

## Percentage representation

Percentages are represented internally as decimal fractions.

Examples:

- 30% is stored as `0.30`
- 3.5% is stored as `0.035`
- 100% is stored as `1.00`

The user interface displays and accepts percentages in familiar percentage
form.

---

## Currency representation

Currency values are represented internally with `Decimal`, not binary
floating-point values.

This prevents avoidable rounding errors in financial calculations.

---

## Override behavior

An event analysis receives a snapshot of applicable business defaults when the
analysis is created.

Changing a saved business default must not silently alter a saved
event-specific value or previously saved analysis.

---

## Database storage representation

The SQLite database stores exact numeric values as scaled integers.

- Currency values are stored as whole cents.
- Percentage values are stored as basis points, where one basis point equals
  0.01 percentage point.
- Labor-entry time values are stored as whole minutes.

Examples:

- $15.00 is stored as 1500 cents.
- $75.00 is stored as 7500 cents.
- 30% is stored as 3000 basis points.
- 3.5% is stored as 350 basis points.
- 12 hours is stored as 720 minutes.

Conversion between database values and application `Decimal` values occurs in
the database-access layer. Scaled database values are never presented directly
to the customer.
