Getting started

  1. Set Business Defaults. Save the values you normally use so each new event starts from a useful baseline.
  2. Create an event analysis. Enter the event details, demand assumptions, costs, labor, and conditions.
  3. Review the results. Check expected sales, total costs, business profit, margin, break-even buyers, and factual warnings.
  4. Test scenarios. Save a new scenario to try different assumptions without overwriting the original. Compare two to four saved scenarios from Saved Events.
  5. Export backups. Visit Data Safety and download a complete backup regularly.

Core concepts

Business Defaults and event inputs
Defaults are reusable starting values. Changes in Event Inputs affect only that event and do not update your Defaults.
Events and Scenarios
An Event holds its name, date, time, and location. Each Scenario is a complete set of assumptions saved for that Event.
Revenue methods
The normal estimate uses attendance-based expected orders and average order sale amount. A custom expected-sales amount can override sales while order-based costs still use estimated orders.
Food and packaging methods
Estimate these costs using an average cost per order, a percentage of sales, or a total for the event.
Profit targets
Choose either a minimum profit amount or minimum profit margin. The target helps compare the calculated outcome with your own goal.
Expected and break-even buyers
Expected buyers are the orders predicted from attendance, food demand, competition, weather, and protection. Break-even buyers are the minimum whole buyers needed to cover the scenario’s current total cost at its average order amount.
Worth it

The scenario is not losing money and meets the selected profit target when one can be evaluated.

Borderline

The scenario is not currently a loss, but it is below the selected profit target.

Not worth it

The scenario has an estimated business loss. The app reports the result; you make the final decision.

Data and safety

Your information is stored in local application data on this device. The app works offline, has no cloud sync, and does not require an account. Completed records are saved automatically through their normal save actions.

Export creates a portable backup. Import validates a backup before replacing current data and creates a recovery snapshot first. Automatic recovery snapshots help protect migrations and restores, but they do not replace your own exported backups.

Deleting saved Events preserves Business Defaults and your local profile. Resetting Defaults preserves saved Events. Clearing all app data removes Defaults, Events, Scenarios, your local profile, and notifications.

Common troubleshooting

Information did not appear to save

Look for a success message and return to the saved screen. Invalid forms preserve your entries but do not partially save. Draft progress and saved Scenarios are different: finish the form or use the Scenario save action when you need a durable result.

A backup import failed

Use a complete .ftbackup file exported by this app. An invalid, damaged, incomplete, or newer-format file is rejected without replacing current data.

A saved event is missing

Open Saved Events and search the event name or location. Confirm that the original Event Inputs form reached the Analysis workspace, which is when the Event and Original estimate are saved.

The numbers look unexpected

Review attendance, shared food demand, competing vendors, weather protection, custom sales, food-cost method, card fees, labor, other costs, and the selected profit target. The Analysis workspace shows calculation details and factual warnings.

Draft or Scenario behavior is confusing

A draft preserves unfinished browser input. A saved Scenario is a complete durable set of event assumptions. Saving a new Scenario keeps the current one; overwrite deliberately replaces the active Scenario.

The app needs to be reset

Open Data Safety. Choose the narrowest action that fits: delete saved Events, reset Business Defaults, or clear all app data. Export a backup first when possible.

Support information
